UniAI CLI vừa kết nối các runtime cục bộ, vừa quản lý không gian làm việc, issue, agent và Tự động hóa từ terminal. Trang này đi qua các luồng thường dùng; tập cờ mà phiên bản bạn cài hỗ trợ luôn do chính `--help` của từng lệnh quy định.

## Cài đặt

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/phanducquanguet/usf/feature/customer-portal/scripts/install.sh | bash
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/phanducquanguet/usf/feature/customer-portal/scripts/install.ps1 | iex
```

Kiểm tra kết quả cài đặt:

```bash
uniai version
```

## Kết nối lần đầu

Kết nối UniAI Cloud:

```bash
uniai setup
```

Kết nối một instance tự lưu trữ:

```bash
uniai setup self-host \
  --server-url https://api.example.com \
  --app-url https://app.example.com
```

`setup` lưu địa chỉ máy chủ, mở trình duyệt để hoàn tất đăng nhập và khởi động daemon. Khi xong, kiểm tra:

```bash
uniai auth status
uniai daemon status
```

Nếu bạn chỉ cần đăng nhập lại mà không ghi đè các cấu hình khác, chạy `uniai login`. Trên máy không có trình duyệt, hãy tạo personal access token trong phần cài đặt trên web trước, rồi nhập token bằng:

```bash
uniai login --token
```

Lệnh này nhắc bạn dán token ngay trong terminal, để giá trị đầy đủ không lọt vào lịch sử shell.

## Chọn không gian làm việc

Liệt kê các không gian làm việc và đổi không gian mặc định:

```bash
uniai workspace list
uniai workspace switch <slug>
```

Các lệnh sau đó dùng không gian làm việc này. Một lệnh đơn lẻ có thể ghi đè bằng `--workspace-id`, hoặc bạn đặt biến `MULTICA_WORKSPACE_ID`.

Mời thành viên:

```bash
uniai workspace member invite teammate@example.com
uniai workspace member invite admin@example.com --role admin
```

## Thao tác issue thường dùng

```bash
# View and search
uniai issue list
uniai issue get UNI-123
uniai issue search "login failure"

# Create and update
uniai issue create --title "Fix login failure"
uniai issue status UNI-123 in_progress
uniai issue assign UNI-123 --to "Backend Agent"

# Comments and runs
uniai issue comment list UNI-123
uniai issue comment add UNI-123 --content "Check the regression tests first"
uniai issue comment update <comment-id> --expected-revision 2 --content "Check the regression tests and release notes"
uniai issue runs UNI-123
```

Đọc mô tả hoặc bình luận dài từ stdin để khỏi phải xử lý xuống dòng và dấu nháy:

```bash
uniai issue create --title "Upgrade notes" --description-stdin < notes.md
uniai issue comment add UNI-123 --content-stdin < review.md
uniai issue comment update <comment-id> --expected-revision 2 --content-file revised-review.md
```

Xem tin nhắn của một lượt chạy, hoặc dừng nó:

```bash
uniai issue run-messages <task-id> --issue UNI-123
uniai issue cancel-task <task-id> --issue UNI-123
```

## Agent và skill

```bash
uniai agent list
uniai agent get <agent-id>
uniai agent create --help
uniai agent update <agent-id> --help

uniai skill list
uniai skill get <skill-id>
uniai skill import --url <skill-url>
uniai agent skills add <agent-id> --skill-ids <skill-id>
```

Khi lệnh nhập gặp skill trùng tên, hành vi mặc định là dừng lại và không sửa nội dung sẵn có. Chọn theo ý định của bạn:

```bash
uniai skill import --url <skill-url> --on-conflict overwrite
uniai skill import --url <skill-url> --on-conflict rename
uniai skill import --url <skill-url> --on-conflict skip
```

`overwrite` chỉ được phép với người tạo skill và giữ nguyên ID gốc cùng các gắn kết agent.

### Lịch sử lượt chạy của agent

`uniai agent tasks <agent-id> --limit 200` trả về trang lượt chạy mới nhất.
Kích thước trang mặc định và tối đa là 200. Nếu còn lượt chạy khác, stderr in ra một
cursor; truyền nguyên giá trị đó vào `--before '<cursor>'` để đọc trang kế tiếp.
`--output json` giữ đầu ra dạng mảng và chỉ kèm usage của trang đó.

Endpoint tương ứng `GET /api/agents/{id}/tasks` nhận `limit` và
`before`, và giữ phản hồi JSON dạng mảng. Response header `X-Agent-Tasks-Next-Cursor`
cung cấp cursor kế tiếp; khi header này vắng mặt nghĩa là đã tới trang cuối.
Cursor giữ thứ tự `(created_at, id)`, kể cả độ chính xác của timestamp.
Limit hoặc cursor không hợp lệ trả về HTTP 400; limit lớn hơn 200 bị giới hạn về 200.
Client không đi theo cursor chỉ nhận được 200 lượt chạy mới nhất.


## Daemon và runtime

```bash
uniai daemon start
uniai daemon stop
uniai daemon restart
uniai daemon status --output json
uniai daemon logs --follow

uniai runtime list
uniai runtime rename <runtime-id> "Office Mac"
uniai runtime usage <runtime-id>
uniai runtime activity <runtime-id>
```

Xóa một runtime vẫn còn agent hoạt động gắn kèm mặc định sẽ bị từ chối. `uniai runtime delete <id> --cascade` gỡ gắn kết các agent đó, giữ nguyên cấu hình và lịch sử của chúng, đồng thời hủy các lượt chạy đang hoạt động.

Xem [Daemon và runtime](/daemon-runtimes) để hiểu cơ chế vận hành và runtime profile tùy chỉnh.

## Tổng quan lệnh

| Lệnh | Mục đích |
| --- | --- |
| `issue` | Tạo, cập nhật, giao và tìm issue; quản lý bình luận, người theo dõi, nhãn, thuộc tính và lượt chạy |
| `project` | Quản lý dự án và tài nguyên của dự án |
| `label`, `property` | Quản lý nhãn và thuộc tính tùy chỉnh của không gian làm việc |
| `agent`, `skill`, `squad` | Quản lý agent, skill và đội |
| `autopilot` | Quản lý Tự động hóa, trigger và lịch sử chạy |
| `workspace` | Tạo, xem và chuyển không gian làm việc, mời thành viên |
| `repo` | Quản lý repo của không gian làm việc và checkout về máy |
| `daemon`, `runtime` | Khởi động và dừng daemon cục bộ; xem và quản lý runtime |
| `attachment` | Tải lên hoặc tải xuống tệp đính kèm |
| `user profile` | Xem hoặc cập nhật hồ sơ người dùng hiện tại |
| `auth`, `login`, `setup` | Đăng nhập, kiểm tra trạng thái xác thực và khởi tạo kết nối |
| `config` | Xem hoặc sửa cấu hình cục bộ của profile CLI hiện tại |
| `update`, `version` | Cập nhật CLI hoặc in phiên bản |

`uniai chat` đọc **phiên chat bên ngoài mà một agent đang xử lý**; lệnh này chủ yếu dành cho agent trong các tích hợp chat, không phải lệnh chung để duyệt hội thoại bất kỳ trong không gian làm việc.

## ID và định dạng đầu ra

Issue dùng mã kiểu `UNI-123` hoặc UUID đầy đủ; tiền tố UUID ngắn không được chấp nhận.

Lệnh `list` của các tài nguyên khác thường in ID ngắn chép-dán được và hỗ trợ `--full-id` để lấy UUID đầy đủ. Khi ID ngắn không đủ để xác định duy nhất, CLI sẽ yêu cầu thêm ký tự hoặc UUID đầy đủ. ID task ngắn còn cần `--issue` để xác định issue chứa nó.

Nhiều lệnh hỗ trợ đầu ra có cấu trúc:

```bash
uniai issue list --output json
uniai agent list --output json
```

Script nên dùng đầu ra JSON thay vì phân tích các bảng vốn dành cho terminal. Định dạng đầu ra và cờ phân trang mà mỗi lệnh hỗ trợ do `uniai <command> --help` quy định.

## Profile và cấu hình

Cấu hình mặc định nằm ở `~/.multica/config.json`. Dùng `--profile <name>` để tách riêng một bộ địa chỉ máy chủ, token, không gian làm việc mặc định và trạng thái daemon:

```bash
uniai setup self-host --profile staging \
  --server-url https://api.staging.example.com \
  --app-url https://app.staging.example.com

uniai issue list --profile staging
```

Các profile có tên nằm ở `~/.multica/profiles/<name>/config.json`. Xem giá trị hiện tại:

```bash
uniai config show
uniai config show --profile staging
```

Đừng đặt `MULTICA_DAEMON_PORT` trong shell của máy chủ, service Compose hay entrypoint của container dùng để khởi động daemon. Daemon trên máy chủ thường tự suy ra cổng health từ `--profile`; nếu không bind được cổng đó, nó dùng một cổng loopback còn trống và tự tiêm cổng thực tế vào các task của agent. Hãy gỡ hẳn biến này khỏi các môi trường khởi động cũ: nếu không, các phiên bản 0.4.22 và 0.4.23 sẽ nhầm shell đó là một task được quản lý và từ chối đăng nhập. Các phiên bản mới hơn cho phép đăng nhập có kiểm soát của con người và `daemon status` tự phục hồi khi cổng là tín hiệu task duy nhất, nhưng các lệnh API thông thường và các lệnh phân giải profile vẫn cố ý từ chối (fail-closed) cho tới khi gỡ biến này.

Khi CLI chạy bên trong một task agent do daemon quản lý, nó không đọc hay sửa các file profile thuộc về con người này. Các lệnh gọi UniAI API xác thực bằng thông tin xác thực phạm vi task do daemon tiêm vào. `config show` và `config set` dùng trạng thái riêng cục bộ theo task; các lệnh dành cho con người/cục bộ như `login`, `logout`, `setup`, `workspace switch`, thay đổi đường dẫn runtime profile cục bộ, `daemon start` / `stop` / `restart`, `daemon logs` và `daemon probe-runtimes` không khả dụng. `auth status` không in nội dung token trong ngữ cảnh này.

`daemon status` và `daemon disk-usage` vẫn khả dụng để agent kiểm tra runtime đang chứa nó, giới hạn trong runtime đó: `status` thăm dò cổng health do daemon tiêm vào, còn `disk-usage` quét thư mục gốc workspaces do daemon tiêm vào. Cả hai đều không nhận `--profile`, `disk-usage` còn từ chối `--all-profiles` và `--workspaces-root`, và cột STATUS của nó để trống vì việc phân giải trạng thái sẽ cần token đã lưu của con người. Dùng `du` và `df` cho mọi thứ ngoài phạm vi đó.

Cơ chế này bảo vệ việc phân giải profile ngầm của UniAI CLI trong khi vẫn giữ nguyên các biến `HOME` và XDG thông thường mà công cụ của các provider (công cụ lập trình AI) khác sử dụng. Đây không phải ranh giới hệ thống tệp ở cấp hệ điều hành: tiến trình chạy dưới cùng một người dùng hệ thống vẫn có thể mở một đường dẫn đã biết rõ. Hãy dùng người dùng riêng, container, VM hoặc mức cách ly tương đương khi cần bảo đảm mạnh hơn.

<Callout type="warning">
File cấu hình CLI chứa token có thể truy cập UniAI với danh nghĩa của bạn. Đừng commit chúng vào repo, đưa chúng lên log hay chia sẻ cho người khác.
</Callout>

## Tham chiếu lệnh

Các bảng dưới đây bao phủ mọi lệnh chính hiện có, nhóm theo đúng cách CLI tự nhóm. Mọi lệnh đều nhận các cờ toàn cục `--server-url`, `--workspace-id`, `--profile` và `--debug`. `--output` được đăng ký theo từng lệnh và định dạng mặc định khác nhau: lệnh `list` mặc định in bảng, còn lệnh `get` và `create` phần lớn mặc định JSON. Cờ đầy đủ do `uniai <command> --help` quy định.

### Lõi

| Lệnh | Lệnh con | Mục đích | Cờ chính |
| --- | --- | --- | --- |
| `issue` | `list` | Liệt kê issue | `--status`, `--priority`, `--assignee`, `--project`, `--metadata` (lặp lại được), `--property` (lặp lại được, `"Name=Value"`; `__none__` khớp giá trị chưa đặt), `--limit`, `--offset`, `--sort` (kể cả `property:<name-or-id>`), `--full-id`, `--resolve-properties` (chỉ JSON; các dòng kèm tên thuộc tính, tùy chọn và thành viên bên cạnh id được lưu) |

| | `label list/add/remove <skill-id>` | Quản lý nhãn trên một skill | `add` / `remove`: `<label-id>` nhận UUID đầy đủ hoặc tiền tố ngắn |
| `squad` | `list/get/create/update/delete` | Quản lý đội (`delete` là lưu trữ) | |

| | `activity <issue-id> <outcome>` | Ghi một đánh giá của leader | |
| `chat` | `history`, `thread [id]` | Đọc phiên chat bên ngoài mà một agent đang xử lý | `--limit`, `--before` |

### Runtime

| Lệnh | Lệnh con | Mục đích | Cờ chính |
| --- | --- | --- | --- |
| `daemon` | `start` | Khởi động daemon cục bộ | `--foreground`, `--device-name`, `--runtime-name`, `--workspaces-root`, `--poll-interval`, `--heartbeat-interval`, `--agent-timeout` (`0` nghĩa là không giới hạn), `--max-concurrent-tasks`, `--no-auto-update`; mỗi cờ có biến môi trường `MULTICA_*` tương ứng |
| | `stop` / `status` / `restart` | Dừng, kiểm tra trạng thái, khởi động lại (`restart` nhận cùng cờ với `start`) | |
| | `logs` | Xem log daemon | `--follow`, `--lines` |
| | `disk-usage` | Xem mức dùng đĩa cục bộ | `--by-workspace`, `--by-task`, `--top` |
| `runtime` | `list/usage/activity/update/rename/delete` | Xem và quản lý runtime | `delete`: `--cascade` (gỡ gắn kết các agent, giữ dữ liệu của chúng và hủy các lượt chạy của chúng) |
| | `profile list/create/update/delete` | Quản lý runtime profile tùy chỉnh | |
| | `profile set-path/unset-path <profile-id>` | Ghim đường dẫn thực thi cục bộ (chỉ cục bộ, không bao giờ tải lên máy chủ) | |

## Điều khiển UniAI từ một coding agent khác

Nếu phần lớn công việc của bạn vốn diễn ra trong Codex, Claude Code hoặc Cursor, bạn có thể
vận hành UniAI ngay từ đó thay vì chuyển sang terminal.
[UniAI CLI skill](https://github.com/multica-ai/multica-cli) dạy các agent đó
dùng các lệnh trên trang này một cách an toàn: đọc issue và chuỗi bình luận
mà không tốn token, viết bình luận qua file, và xử lý các tác dụng phụ
đi kèm @nhắc, đổi trạng thái và giao việc.

Skill chạy hoàn toàn qua CLI đã xác thực của bạn và không tự cấp quyền truy cập nào —
quyền vẫn đến từ phiên đăng nhập, profile đã chọn và không gian làm việc của bạn. Skill cần
CLI v0.4.26 trở lên. README của repository hướng dẫn cài đặt cho plugin marketplace của
Claude Code, trình cài skill của Codex, Cursor và mọi công cụ khác nạp được
chỉ dẫn dạng Markdown.
