Tài nguyên của [dự án](/projects) cho agent biết phần việc này dùng mã nguồn nào và chạy ở đâu. Tài nguyên gắn liền với dự án, nên không cần dán lại URL repository hay đường dẫn cục bộ vào từng issue.

Hiện hỗ trợ hai kiểu tài nguyên:

| Tài nguyên | Phù hợp khi | Chạy ở đâu |
|---|---|---|
| **Repository GitHub** | Mã nguồn cả nhóm dùng chung, checkout do runtime quản lý | Thư mục làm việc do runtime quản lý |
| **Thư mục cục bộ** | Một bản checkout sẵn có, repository rất lớn, hoặc khi bạn muốn xem trực tiếp các thay đổi trên máy | Chính thư mục gốc trên một máy cụ thể |

## Tài nguyên đi vào lần chạy như thế nào

Khi agent xử lý issue trong dự án, UniAI thêm tên dự án, mô tả dự án và danh sách tài nguyên vào ngữ cảnh của lần chạy, đồng thời ghi `.multica/project/resources.json` vào thư mục làm việc.

Danh sách repository gắn với không gian làm việc luôn có mặt trong ngữ cảnh của lần chạy. Repository gắn với dự án thì chỉ rõ thêm mã nguồn và ref mặc định mà phần việc này dùng.

Thư mục cục bộ chỉ áp dụng cho daemon nó được gắn. Khi daemon chạy task có thư mục cục bộ khớp, agent làm việc trực tiếp trong thư mục đó; các máy khác vẫn dùng repository GitHub của dự án hoặc repository của không gian làm việc.

## Thêm repository GitHub

Mở dự án và chọn "Add resource" dưới mục **Resources**. Chọn một repository đã gắn với không gian làm việc, hoặc dán một URL Git. Repository của không gian làm việc được quản lý ở **Settings → Repositories**; sau khi kết nối GitHub, trang này có thêm **Pick from GitHub** để nhập các repository mà App được cấp quyền.

Repository không giới hạn ở GitHub: mọi URL Git mà runtime truy cập được đều dùng được làm tài nguyên repository. Bản UniAI self-hosted còn kết nối được Forgejo, Gitea hoặc GitLab tự vận hành ở **Settings → Integrations → Git hosting**; xem [Git provider tự vận hành](/vcs-integration).

Khi tạo dự án, bạn cũng chọn được repository ngay dưới mục **Repos**. Một dự án gắn được nhiều repository GitHub.

`ref` của tài nguyên đặt nhánh, tag hoặc commit mà các lần checkout sau dùng làm mặc định. `default_branch_hint` chỉ gợi ý nhánh mặc định cho agent và không ép chuyển nhánh.

## Thêm thư mục cục bộ

Thêm thư mục cục bộ cần một daemon đang chạy trên máy đó, vì trình duyệt không thể chọn thư mục trên máy của bạn.

<Callout type="warning">
**Đây là lối thoát hiểm, không phải một mặc định tiện hơn.** `local_directory` tồn tại cho những ai không còn lựa chọn khác — trường hợp điển hình là dự án game với bản checkout hàng chục gigabyte, nơi clone lại theo từng task đơn giản là bất khả thi.

Nếu thư mục của bạn là một repo git bình thường clone được, **hãy dùng `github_repo`**: nó mặc định chạy ở chế độ worktree, nên các task trên cùng repo chạy song song không giới hạn. Chọn `local_directory` nghĩa là mọi task trên thư mục đó chạy **tuyệt đối tuần tự, mỗi lúc một task, mãi mãi**. Đọc kỹ phần "khi nào chọn" bên dưới trước khi quyết định.
</Callout>


1. Đảm bảo daemon cục bộ trên máy này đang online.
2. Mở mục **Resources** của dự án.
3. Chọn "Add local directory", rồi chọn thư mục muốn dùng.

Thư mục phải là đường dẫn tuyệt đối, phải tồn tại sẵn, và daemon hiện tại phải đọc và ghi được. Các đường dẫn sau bị từ chối: gốc hệ thống và gốc ổ đĩa (`/`, `C:\`), chính thư mục home và thư mục cha của các thư mục home (như `/Users`, `/home`, `/root`), cùng các thư mục hệ thống như `/etc`, `/var`, `/tmp`, `/usr` và `/opt`. Nếu đường dẫn được chọn là symlink, nó được phân giải về đường dẫn thật trước rồi kiểm tra lại theo cùng bộ quy tắc; khóa tuần tự cũng áp dụng trên đường dẫn thật.

Mỗi dự án gắn được tối đa một thư mục cục bộ cho mỗi daemon. Các máy khác nhau trong nhóm đều gắn được thư mục riêng của mình cho cùng một dự án.

<Callout type="warning">
Thư mục cục bộ không phải môi trường cách ly. Agent nhìn thấy và sửa trực tiếp nhánh hiện tại cùng các file chưa commit của bạn; UniAI không tự chuyển nhánh, stash, commit, push hay mở PR.
</Callout>

## Thư mục cục bộ chạy tuần tự

Khi hai task dùng cùng một thư mục thật, task đến sau vào trạng thái `waiting_local_directory` và tiếp tục sau khi task trước nhả thư mục. Hai đường dẫn dẫn tới cùng một thư mục qua các symlink khác nhau cũng tuần tự hóa như vậy.

Việc chờ không đụng vào thư mục. Task đang chờ có thể bị hủy; nếu không, nó chờ tới khi thư mục sẵn sàng.

Muốn làm nhiều thay đổi cùng lúc, hãy dùng tài nguyên repository GitHub để runtime chuẩn bị thư mục làm việc riêng cho từng phần việc.

## Những gì được ghi trong lần chạy

Ngoài các thay đổi mã do agent thực hiện, runtime còn có thể ghi vào thư mục các file hướng dẫn mà công cụ lập trình AI hiện tại cần, cùng `.multica/project/resources.json`. Thêm chúng vào `.gitignore` nếu bạn không muốn đưa vào quản lý phiên bản.

UniAI không bao giờ xóa một thư mục cục bộ đã gắn khi dọn dẹp môi trường chạy. Thay đổi của agent trong thư mục cũng giống hệt thay đổi khi bạn tự chạy một công cụ lập trình AI trong terminal, và cần được review y như vậy.

## Quản lý tài nguyên bằng CLI

```bash
# Gắn repository khi tạo dự án
uniai project create \
  --title "Agent UX" \
  --repo https://github.com/phanducquanguet/usf

# Liệt kê và thêm tài nguyên
uniai project resource list <project-id>
uniai project resource add <project-id> \
  --type github_repo \
  --url https://github.com/phanducquanguet/usf \
  --ref main

# Gắn thư mục cục bộ trên một daemon cụ thể
uniai project resource add <project-id> \
  --type local_directory \
  --local-path /absolute/path/to/repo \
  --daemon-id <daemon-id>

# Gỡ một tài nguyên
uniai project resource remove <project-id> <resource-id>
```

Thay đổi tài nguyên chỉ ảnh hưởng các task tạo sau đó; nó không viết lại hồ sơ của những lần chạy đã kết thúc.
