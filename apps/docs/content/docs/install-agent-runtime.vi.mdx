Một runtime cục bộ gồm hai phần: UniAI daemon và một công cụ lập trình AI mà daemon gọi được. Chỉ cần cài công cụ bạn định dùng — không cần đủ tất cả.

## 1. Chọn công cụ

## 2. Đăng nhập trên máy của bạn

Sau khi cài, tự chạy công cụ một lần trong terminal và hoàn tất đăng nhập hoặc thiết lập nhà cung cấp model. Nếu công cụ không hoàn thành được yêu cầu trong terminal, các lần gọi từ daemon cũng lỗi y như vậy.

Với CodeArts, hãy kiểm chứng đường không tương tác bằng `codearts run --model provider/model "Reply OK"`, không chỉ qua TUI. CodeArts CLI hiện tại có thể để một provider tùy chỉnh chạy được trong TUI trong khi `run`, `models` và `serve` vẫn yêu cầu [`CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`](https://support.huaweicloud.com/usermanual-cli/codeartsagent_cli_0026.html). UniAI có thể phát hiện model tùy chỉnh từ `~/.codeartsdoer/codearts_cli.json` hoặc `.jsonc`, nhưng lượt chạy của agent dùng `codearts run` nên phải tuân theo yêu cầu xác thực của nó.

Với Reasonix, chạy `reasonix setup` và cấu hình provider cùng model mặc định trước khi khởi động daemon.

Với QwenPaw, chọn provider và model trong cấu hình riêng của QwenPaw. UniAI không ghi đè được model của QwenPaw lúc chạy.

Với MiniMax Code, cài một bản Node.js được hỗ trợ (`>=22.19 <23` hoặc `>=24 <27`) rồi chạy `npm install --global @minimax-ai/code@latest`. Cài npm toàn cục sẽ đặt `mcode` vào đường dẫn binary toàn cục của npm; nếu `command -v mcode` hoặc `Get-Command mcode` không tìm thấy, hãy thêm đường dẫn đó vào `PATH`. Sau đó chạy `mcode login`. MiniMax Code tự quản lý việc chọn model; UniAI không ghi đè được qua ACP.

Với DeepSeek Harness, cài Node.js 20+ và chạy `npm install -g @deepseek-ai/dsh`, rồi cấp cho nó runtime profile của UniAI — bundle cài đặt giao thức `--stdio` mà UniAI điều khiển, và là lý do một `dsh` trần không tự dùng được. Đặt `MULTICA_DSH_PROFILE_BUNDLE` thành bundle cần cài và daemon sẽ thêm giúp bạn, hoặc tự thêm bằng `dsh plugin --profile multica add <bundle>`. `<bundle>` là bất cứ thứ gì `dsh plugin` chấp nhận — tên package npm, một thư mục, hoặc một tarball đã đóng gói — và cầu nối nằm tại [multica-ai/dsh-multica-runtime](https://github.com/multica-ai/dsh-multica-runtime). Nó chưa có trên registry npm công khai ([multica#6936](https://github.com/multica-ai/multica/issues/6936)), nên hiện tại bạn build nó từ repository đó rồi trỏ biến tới thư mục build, hoặc tới tarball mà `npm pack` tạo ra — dùng cách sau nếu máy chạy daemon không phải máy đã build. Tên package sẽ là lựa chọn đơn giản nhất khi cầu nối được phát hành. Dù chọn cách nào, hãy ưu tiên thứ do chính đội bạn phát hành hoặc build: giá trị này được cài vào DSH home của mọi máy chạy daemon mà không cần xác nhận thêm, nên một package bên thứ ba chưa được thẩm định là quyết định về chuỗi cung ứng, không phải chuyện tiện lợi. Nếu bạn cài DeepSeek Harness Desktop thay vì package npm, daemon cũng tìm các CLI shim mà ứng dụng đó tạo ra, trong thư mục dữ liệu riêng theo người dùng của nó — `~/Library/Application Support/DSH Desktop` trên macOS, `%APPDATA%\DSH Desktop` trên Windows. Trên Windows đó là dữ liệu ứng dụng roaming, không phải thư mục cài đặt: ứng dụng cài vào Program Files hoặc `%LOCALAPPDATA%\Programs`, nhưng CLI mà nó điều khiển nằm cạnh các trạng thái riêng theo người dùng khác. Phân đoạn phiên bản trong các đường dẫn đó là một id được sinh ra, nên daemon liệt kê chúng và ưu tiên bản mới nhất. Không cần thêm gì vào `PATH` — shim được sinh ra chạy runtime riêng của ứng dụng Desktop qua đường dẫn tuyệt đối. Nếu DSH Desktop được cài ở vị trí không mặc định, hãy trỏ `MULTICA_DSH_PATH` tới shim. Daemon chỉ đăng ký DeepSeek Harness sau khi `dsh --profile multica --probe` thành công, và báo profile còn thiếu trên `/health` khi không thành công. Đặt `DEEPSEEK_API_KEY` (hoặc lưu nó trong cài đặt riêng của dsh) trước khi khởi động daemon.

Các thông tin đăng nhập đó do chính công cụ lưu cục bộ. UniAI không bao giờ nhận token đăng nhập từ Claude, Codex, Cursor hay bất kỳ CLI nào khác.

<Callout type="info">
Antigravity yêu cầu từ 1.1.10 trở lên, Claude Code từ 2.0.0, Codex từ 0.100.0, Copilot từ 1.0.0, Grok từ 0.2.89, Qwen Code từ 0.20.0, MiniMax Code từ 0.1.2 và OpenCode từ 1.1.54. Dưới phiên bản tối thiểu, daemon không đăng ký runtime tương ứng.
</Callout>

## 3. Xác nhận daemon tìm thấy lệnh

Trên macOS, Linux hoặc WSL, chạy:

```bash
command -v <command>
<command> --version
```

Trong Windows PowerShell, chạy:

```powershell
Get-Command <command>
<command> --version
```

Thay `<command>` bằng một lệnh trong bảng, ví dụ `claude`, `codex` hoặc `cursor-agent`. Lệnh đầu tiên in ra đường dẫn file thực thi.

Nếu terminal tìm thấy công cụ nhưng daemon chạy nền thì không, thường là hai bên đang dùng giá trị `PATH` khác nhau. Khởi động lại daemon, hoặc đặt đường dẫn tuyệt đối qua biến môi trường `MULTICA_<PROVIDER>_PATH` tương ứng.

## 4. Quét lại và xác nhận runtime online

Khởi động daemon bằng CLI:

```bash
uniai daemon start
```

Nếu daemon đang chạy sẵn, khởi động lại nó sau khi cài công cụ mới:

```bash
uniai daemon restart
```

Sau đó mở trang **Runtime** của UniAI. Công cụ hiện dưới máy tính tương ứng và ở trạng thái online. Giờ bạn có thể chọn runtime này khi tạo hoặc chỉnh sửa agent.

<Callout type="warning">
Daemon phải phát hiện được ít nhất một CLI được hỗ trợ sẵn thì mới khởi động. Các profile runtime tùy chỉnh chỉ đồng bộ sau khi daemon đã chạy, nên trên một máy trắng chúng không thể là điều kiện khởi động duy nhất. Có một ngoại lệ: khi daemon vừa tự bắt đầu cài runtime profile DSH (`MULTICA_DSH_PROFILE_BUNDLE`), nó khởi động mà không có runtime nào và đăng ký DeepSeek Harness khi việc cài đặt hoàn tất. Nếu không có ngoại lệ này, một máy chỉ có DSH cần profile sẽ không bao giờ cài xong được — daemon sẽ thoát trước khi cài xong và kéo theo việc cài đặt dừng lại.
</Callout>

## Không phát hiện được công cụ nào

Kiểm tra theo thứ tự:

1. Tự chạy công cụ trong terminal để xác nhận đã cài và đã đăng nhập xong.
2. Kiểm tra tên lệnh và đường dẫn thực tế bằng `command -v` hoặc `Get-Command`.
3. Chạy `uniai daemon logs -f` và tìm lỗi về phiên bản, đường dẫn hoặc xác thực.
4. Khởi động lại daemon để nó đọc lại môi trường hiện tại.
5. Quay lại trang **Runtime** và xác nhận máy tính lẫn công cụ đều online.

Nếu công cụ hiện online nhưng các lần chạy vẫn lỗi, mở bản ghi chạy của issue để xem chính xác lỗi mà CLI trả về.
