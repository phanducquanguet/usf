Trong sử dụng hằng ngày với UniAI, bạn chủ yếu gặp hai loại thông tin xác thực: phiên đăng nhập trình duyệt và personal access token. Phiên trình duyệt phục vụ ứng dụng web; personal access token phục vụ CLI, daemon, script và API.

## Phiên đăng nhập trình duyệt

Sau khi đăng nhập bằng mã xác thực qua email hoặc Google, UniAI lưu một JWT trong cookie HttpOnly tên `multica_auth`. Trình duyệt tự động gửi nó; JavaScript không đọc trực tiếp được.

Phiên kéo dài 30 ngày theo mặc định. Quản trị viên tự host có thể chỉnh vòng đời của các phiên cấp từ đó về sau bằng `AUTH_TOKEN_TTL`. Đăng xuất sẽ xóa cookie xác thực và cookie CSRF trong trình duyệt hiện tại.

Cookie trình duyệt không dành để chép vào script hay CLI; hãy dùng personal access token để truy cập UniAI từ terminal.

## Personal access token

Personal access token (PAT) bắt đầu bằng `mul_` và đại diện cho tài khoản của bạn. Nó truy cập được mọi không gian làm việc và API mà bạn có quyền, nên hãy giữ nó như giữ mật khẩu.

Khi tạo token ở **Cài đặt → API Token**, bạn đặt tên và chọn hạn dùng 30 ngày, 90 ngày, 1 năm hoặc vĩnh viễn; 90 ngày được chọn sẵn. Token đầy đủ chỉ hiển thị đúng một lần; sau khi hộp thoại đóng, UniAI chỉ giữ lại:

- hash của token;
- vài ký tự đầu, để nhận diện;
- tên, thời điểm tạo, hạn dùng và lần dùng cuối.

Giá trị đầy đủ không thể khôi phục. Nếu làm mất, hãy thu hồi token cũ và tạo cái mới.

<Callout type="warning">
Đừng đặt PAT vào repo, issue, bình luận, ảnh chụp màn hình hay log, và đừng truyền nó trực tiếp trong các lệnh shell được lưu lại.
</Callout>

## CLI và PAT

Khi bạn chạy `uniai login`, CLI hoàn tất đăng nhập qua trình duyệt, rồi tạo một PAT có hạn 90 ngày và lưu vào file cấu hình của profile hiện tại:

```text
~/.multica/config.json
~/.multica/profiles/<name>/config.json
```

Daemon kết nối tới UniAI bằng chính PAT này. PAT `mul_` có hạn dùng sẽ tự gia hạn khi còn dưới 7 ngày, kéo dài thành 90 ngày tính từ thời điểm đó. Gia hạn thất bại thì token giữ nguyên; một khi token đã hết hạn hoặc bị thu hồi, hãy chạy `uniai login` lại.

Trên máy không có trình duyệt, hãy tạo PAT trên web trước rồi để CLI hỏi nhập nó một cách an toàn:

```bash
uniai login --token
```

## Dùng PAT trong request API

Đặt PAT vào header `Authorization`:

```bash
export MULTICA_TOKEN='mul_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'

curl https://uniai.unicomhub.com/api/me \
  -H "Authorization: Bearer $MULTICA_TOKEN"
```

Các lệnh gọi API mức không gian làm việc còn cần chỉ định không gian làm việc, theo yêu cầu của endpoint:

```bash
curl https://uniai.unicomhub.com/api/issues \
  -H "Authorization: Bearer $MULTICA_TOKEN" \
  -H "X-Workspace-ID: $MULTICA_WORKSPACE_ID"
```

Trong script, hãy lấy token từ một secret manager hoặc biến môi trường được bảo vệ — không bao giờ hardcode. Trên bản tự host, thay domain bằng địa chỉ API công khai của bạn.

## Đăng xuất và thu hồi

`uniai auth logout` chỉ xóa PAT lưu trong profile CLI hiện tại; đăng xuất trên web chỉ xóa cookie của trình duyệt hiện tại. Cả hai đều không thu hồi personal access token trên server.

Nếu token có khả năng đã lộ, hãy thu hồi ngay ở **Cài đặt → API Token**. Sau khi thu hồi, PAT vĩnh viễn không dùng được nữa, và mọi máy hay script khác đã lưu nó cũng mất quyền truy cập.

## Token tạm thời cho lượt chạy của agent

Khi daemon nhận một task, server tạo một token tạm thời cho lượt chạy đó, tiền tố `mat_`. Nó bị gắn với người dùng, không gian làm việc, agent và task hiện tại, có hiệu lực tối đa 24 giờ, và được dọn dẹp khi task kết thúc.

Daemon tiêm token tạm thời này vào công cụ lập trình AI thay vì trao PAT của người dùng cho agent. Nhờ vậy các request agent thực hiện được ghi nhận là hành động của agent, và token này không dùng được để chạm tới các thao tác nhạy cảm dành riêng cho người dùng hoặc owner.

Các token này do server tự động tạo; người dùng không bao giờ cần lưu hay quản lý chúng.

## Các thông tin xác thực máy khác

Server còn nhận diện hai loại thông tin xác thực dùng trong các kịch bản nội bộ hoặc được quản lý hộ:

| Tiền tố | Mục đích | Ai quản lý |
| --- | --- | --- |
| `mcn_` | Kết nối UniAI Cloud Node | UniAI Cloud Fleet |
| `mdt_` | Giao thức xác thực daemon phạm vi không gian làm việc | Các luồng nội bộ của server |

Các bản cài Cloud và tự host thông thường không bao giờ cần tự tạo chúng. CLI và daemon phía người dùng luôn dùng PAT `mul_`; đừng tự dựng token với tiền tố khác.
